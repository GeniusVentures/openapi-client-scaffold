# Phase 6 — Core UI Foundation UI Design Contract

> Visual and interaction contract for the 28 widget atoms + ScaffoldMotion that form the universal UI foundation for all Genius Network consumer apps. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Project type:** Flutter / Dart (shadcn gate not applicable — no React/Next.js/Vite toolchain).
**Design standard:** Material 3. Material Design 3 governs over web/shadcn-origin heuristics.
**Phase type:** Widget atom library — not app screens. Atoms are generic, composable primitives that consume only `Theme.of(context)` via `context.palette`/`context.dimens`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter/Dart — shadcn not applicable) |
| Preset | not applicable |
| Component library | Material 3 (Flutter `ThemeData` / `ColorScheme` / `ThemeExtension`) |
| Icon library | Material Icons (`Icons.*` from `package:flutter/material.dart`) |
| Font | System font (SF Pro on iOS/macOS, Roboto on Android) — atoms use `Theme.of(context).textTheme`, no custom fonts |
| State management | None in atoms — pure `StatefulWidget`/`StatelessWidget`. Template-generated composites use Cubit (`flutter_bloc`) for hydrated variant state. Riverpod is consumer app scope only — never in the scaffold. |
| Theme system | `frontend_scaffold` M3 `ThemeExtension` triple: `ScaffoldPalette` + `ScaffoldDimens` + `ScaffoldElevation` |
| Package | `frontend_scaffold` (at `src/scaffold/`) — export barrel at `lib/frontend_scaffold.dart` |

### Existing Theme Infrastructure

Atoms do NOT re-invent theming. They consume the established token system:

| Token Class | Type | Tokens | Pattern |
|-------------|------|--------|---------|
| `ScaffoldPalette` | `ThemeExtension<ScaffoldPalette>` | 15 semantic color tokens + 7 new in Wave 0 (see Color section) | `copyWith` / `lerp` |
| `ScaffoldDimens` | `ThemeExtension<ScaffoldDimens>` | 17 spacing/sizing tokens + 6 new in Wave 0 (see Spacing section) | `copyWith` / `lerp` |
| `ScaffoldElevation` | Static class | `card` shadow list (black @ 35%, blur 16px, offset y 4) | Constants |
| `ScaffoldBreakpoints` | Static class | `small` (760), `tablet` (1200), `medium` (1644), `large` (1920) | `MediaQuery` + platform detection |
| `ScaffoldThemeX` | `BuildContext` extension | `context.palette` → `ScaffoldPalette`, `context.dimens` → `ScaffoldDimens` | `??` fallback to defaults |

**Lookup pattern (mandatory for all atoms):**
```dart
final palette = context.palette;
final dimens = context.dimens;
final textTheme = Theme.of(context).textTheme;
final colorScheme = Theme.of(context).colorScheme;
```

Atoms resolve colors/dimensions from these tokens — never from hardcoded hex or numeric literals. The fallback chain (`context.palette ?? ScaffoldPalette.defaultPalette`) means any consumer app gets sensible defaults if it doesn't register theme extensions.

## Spacing Scale

All spacing uses multiples of 4, inherited from the 01-UI-SPEC (Touch POS) and 09-UI-SPEC (Admin) design language. The existing `ScaffoldDimens` tokens are the primary spacing vocabulary.

### Existing ScaffoldDimens Tokens

| Token | Value (px) | Usage |
|-------|------------|-------|
| `space2` | 4 | Icon gaps, inline padding, tight element spacing |
| `space3` | 6 | Compact element spacing (legacy; prefer `space4`) |
| `space4` | 8 | Compact element spacing, icon-label gap |
| `space6` | 12 | Intermediate element spacing |
| `space8` | 16 | Default element spacing, card inner padding |
| `space12` | 24 | Section padding, headline-body gap |
| `itemSpacing` | 16 | Stacked item spacing (alias for `space8`) |
| `horizontalPadding` | 20 | Page-level horizontal padding (phone) |
| `horizontalDesktopPadding` | 40 | Page-level horizontal padding (desktop) |
| `verticalDesktopPadding` | 40 | Page-level vertical padding (desktop) |
| `borderRadiusCard` | 15 | Card and surface corner radius |
| `borderRadiusButton` | 48 | Button corner radius (pill) |
| `radiusMd` | 12 | Medium corner radius (alert cards) |
| `radiusPill` | 48 | Full pill radius |
| `appBarHeight` | 65 | App bar height |

### Wave 0 Dimens Additions (D-03)

| Token | Value (px) | Usage |
|-------|------------|-------|
| `focusRingWidth` | 2 | ScaffoldFocusOutline stroke width |
| `skeletonCornerRadius` | 4 | ScaffoldSkeleton box corner radius |
| `disabledOverlayOpacity` | 0.40 | ScaffoldDisabledOverlay alpha |
| `dragHandleSize` | 24 | ScaffoldDragHandle width (centered in a 48px touch target) |
| `minTouchTarget` | 48 | Minimum touch target in both dimensions |
| `touchTargetPadding` | 12 | Internal padding to achieve 48px on smaller content |

### Enforced Touch Target

**Hard contract: 48px minimum touch target** (inherited from 01-UI-SPEC). Every interactive atom — ScaffoldTouchTarget, ScaffoldPressable, ScaffoldBadge, ScaffoldNumericInput, ScaffoldSelectableSurface, ScaffoldDragHandle, ScaffoldResizeHandle — must have a minimum 48px in both width and height of the interactive hit area. The checker will flag any interactive widget below 48px.

`ScaffoldTouchTarget` is the canonical enforcement atom — it wraps any child and guarantees the 48px minimum by adding transparent padding when the child is smaller. All other interactive atoms either compose `ScaffoldTouchTarget` or use `dimens.minTouchTarget` with `dimens.touchTargetPadding` to achieve the same constraint.

## Typography

Atoms are **typography-neutral**. They do NOT declare font families, sizes, or weights — consumers wire the textTheme through `ThemeData.textTheme`. Atoms only consume:

```dart
final textTheme = Theme.of(context).textTheme;
```

This means any consumer app can set its own Material 3 typescale (Touch POS uses 16/400 body, Admin uses 14/400 body) and atoms render with that scale.

### Atom-level Typography Conventions

Atoms follow Material 3 text role conventions. When an atom renders a label or value, it maps to a standard M3 role:

| Atom Context | M3 Text Role | Notes |
|-------------|-------------|-------|
| ScaffoldBadge count/label | `textTheme.labelSmall` | Compact badge text — consumer overrides via `textTheme` if needed |
| ScaffoldFormattedValue output | `textTheme.bodyLarge` | Formatted number/money/date display |
| ScaffoldStatusIndicator label | `textTheme.labelMedium` | Accessible label — rendered for Semantics, visually hidden by default |
| ScaffoldNumericInput value | `textTheme.bodyLarge` | Current numeric value display |
| ScaffoldSearchBar hint | `textTheme.bodyLarge` with `hintColor` | Template-generated composite — textTheme from consumer |
| ScaffoldCard header | `textTheme.titleMedium` | Template-generated composite — textTheme from consumer |
| ScaffoldStateView message | `textTheme.bodyLarge` | Empty/error/loading state message — text from consumer |

**No atom hardcodes a font size.** If an atom needs default text styling, it uses `DefaultTextStyle.of(context).style` or the nearest `textTheme` role. Consumer apps set their own typescale; atoms render it.

### Typography Bridging (for planner/executor)

The atoms must support BOTH upstream type scales without modification:
- **Touch POS scale (mobile):** Body 16/400/1.5, Label 14/500/1.4, Heading 24/600/1.2, Display 36/700/1.1
- **Admin scale (desktop):** Body 14/400/1.5, Label 14/600/1.4, Heading 16/600/1.3, Display 24/600/1.2

Since atoms only read `Theme.of(context).textTheme`, they automatically render in either scale — the consumer's `ThemeData` supplies the typescale. The planner must verify each atom works with both scale extremes (14px-16px body, 24px-36px display).

## Color — ScaffoldPalette Token Contract

The `ScaffoldPalette` is the canonical color source for all atoms. Atoms resolve colors through `context.palette` — never from hardcoded hex values. Consumer apps override the palette by registering a different `ScaffoldPalette` instance on `ThemeData.extensions`.

### Existing Palette Tokens (15 tokens)

| Token | Dark Default | Usage |
|-------|-------------|-------|
| `deepBlueCardColor` | `#0A121F` | Card/raised-surface backgrounds |
| `lightGreenPrimary` | `#00EAAE` | Primary accent — focus ring, active indicators |
| `lightGreenSecondary` | `#01CC95` | Secondary accent — icon tints |
| `gray500` | `#73788C` | Muted text, secondary labels |
| `blue500` | `#0068EF` | Accent blue |
| `borderGrey` | `rgba(255,255,255,0.30)` | Enabled input borders |
| `grayPrimary` | `rgba(21,30,41,1)` | Input fill |
| `deepBlueTertiary` | `#05090F` | Deepest surface — drawers, bottom sheets |
| `surfaceElevated` | `#0C0E14` | Elevated surface fill — toasts, overlays |
| `borderSubtle` | `rgba(255,255,255,0.12)` | Hairline borders on elevated surfaces |
| `textPrimary` | `#FFFFFF` | Primary text on dark surfaces |
| `textSecondary` | `#8A8F9D` | Secondary text on dark surfaces |
| `statusSuccess` | `#0AD89C` | Success status indicator |
| `statusError` | `#FF4D4D` | Error status indicator |
| `statusWarningText` | `#FFC42E` | Warning status foreground |

### Wave 0 Palette Additions (D-03 — 7 new tokens)

| Token | Dark Default | Usage |
|-------|-------------|-------|
| `focusRingColor` | `lightGreenPrimary` (default — same as existing primary accent) | ScaffoldFocusOutline ring color — visible in all states (keyboard + screen reader) |
| `skeletonBaseColor` | `surfaceElevated` (`#0C0E14`) | ScaffoldSkeleton base background |
| `skeletonShimmerColor` | `deepBlueCardColor` (`#0A121F`) | ScaffoldSkeleton shimmer animation color |
| `disabledOverlayColor` | `rgba(0,0,0,0.40)` | ScaffoldDisabledOverlay dim color (dark theme) |
| `dragFeedbackBackground` | `surfaceElevated` (`#0C0E14`) with elevated shadow | ScaffoldDraggable drag-feedback chip background |
| `dropZoneHighlight` | `lightGreenPrimary` at 20% opacity | ScaffoldDropTarget accepted/over state |
| `dropZoneRejected` | `statusError` at 20% opacity | ScaffoldDropTarget rejected state |

**Light-theme fallback:** When a consumer app registers a light palette on `ThemeData.extensions`, the new tokens derive from the light theme's surface/card colors (e.g., `disabledOverlayColor` becomes `rgba(255,255,255,0.70)`, `skeletonBaseColor` maps to the light card surface). The `ScaffoldPalette.defaultPalette` is dark-seeded; consumer apps that need light themes must provide their own `ScaffoldPalette` with appropriate light-token values.

### 60/30/10 Model — Not Applicable to Atom Library

The 60/30/10 color split (dominant/secondary/accent) applies to **app screens**, not to a widget atom library. Atoms are painted by their consuming app's theme. The atoms themselves are themeless — they read tokens, not palette roles. The 60/30/10 split is established by the consumer's `ThemeData` and the `ScaffoldPalette` instance it registers, not by the atoms.

However, for atom-level consistency:

**Accent-lightGreenPrimary reserved for (within atoms):**
- `ScaffoldFocusOutline` ring color
- `ScaffoldStatusIndicator` active/selected fill
- `ScaffoldSelectionIndicator` checked/selected state
- `ScaffoldBadge` dot color (configurable — caller may override)
- `ScaffoldNumericInput` increment/decrement button active state
- `ScaffoldDragHandle` drag-active highlight

**Destructive-statusError reserved for (within atoms):**
- `ScaffoldStatusIndicator` error state
- `ScaffoldDropTarget` rejected state
- `ScaffoldFileInputSurface` validation error state
- `ScaffoldStateView` error variant background tint

**Success-statusSuccess reserved for (within atoms):**
- `ScaffoldStatusIndicator` success/completed state
- `ScaffoldDropTarget` accepted/dropped state
- `ScaffoldFileInputSurface` valid file selected state

## Visual Contracts — Per Atom Category

### Wave 0: Zero-Dependency Foundations (10 widgets + ScaffoldMotion)

#### ScaffoldMotion (_utility + InheritedWidget_)

**Visual:** No visual component. Provides static animation constants and a reduced-motion InheritedWidget.

- **Static durations:** `short` (150ms), `medium` (300ms), `long` (500ms)
- **Static curves:** `standard` (`easeInOut`), `decelerate` (`easeOut`), `emphasized` (`easeInOut` with slight overshoot)
- **InheritedWidget:** `ScaffoldMotion(reducedMotion: bool, child: Widget)` — widgets read `ScaffoldMotion.of(context).reducedMotion`
- **Reduced motion:** When `true`, all scaffold atoms substitute zero-duration transitions or fades instead of motion-based animations (path, scale, slide, rotate, shake, bounce)

#### ScaffoldSurface (_background + border container_)

**States:** default (idle)
**Visual:**
- Renders a container with configurable `color` (default: `palette.deepBlueCardColor`), `borderRadius` (default: `dimens.borderRadiusCard`), `border` (default: null), `elevation` (default: 0 with no shadow).
- Exposes `shape` (RoundedRectangleBorder or BoxShape.circle) and `padding`.
- NO content knowledge — renders whatever `child` is passed, purely a visual wrapper.

**Contract:** `ScaffoldSurface({color, borderRadius, border, elevation, padding, shape, child})`

#### ScaffoldTouchTarget (_48px hit-area enforcer_)

**States:** default
**Visual:**
- Transparent wrapper around `child`. Adds transparent padding to ensure min 48x48 hit area.
- No visible decoration — purely an interaction-area enforcer.
- Registers `Semantics` with `container: true` so screen readers identify the touch region.

**Contract:** `ScaffoldTouchTarget({child, minWidth: 48, minHeight: 48})`
**Enforcement:** Planner must add widget tests asserting `hitTest` returns `true` for a 48x48 area centered on the child.

#### ScaffoldFocusOutline (_focus ring painter_)

**States:** unfocused, focused (keyboard), focused (accessibility)
**Visual:**
- Renders a `CustomPaint` overlay that draws a rounded-rect border using `palette.focusRingColor` at `dimens.focusRingWidth` (2px), inset from the widget bounds by 1px.
- Visible when: `FocusNode.hasFocus == true` AND (`FocusManager.instance.keyboardFocus` is active OR `MediaQuery.of(context).accessibleNavigation == true`).
- Uses `BorderRadius` matching the nearest parent surface's border radius when the focus ring is not explicit.

**Contract:** `ScaffoldFocusOutline({child, focusNode, borderRadius, ringColor, ringWidth})`
**Accessibility:** Focus ring MUST be visible when TalkBack/VoiceOver is active (via `accessibleNavigation`), not just keyboard focus.

#### ScaffoldLiveRegion (_screen-reader announcements_)

**States:** announcing (transient), idle
**Visual:** No visible component. A zero-size widget that wraps `Semantics(liveRegion: true)` around the content it announces.
- When the `label` or `value` changes, screen readers announce the change.
- Used by atoms that report changing values: `ScaffoldNumericInput`, `ScaffoldFormattedValue`, `ScaffoldStatusIndicator`.

**Contract:** `ScaffoldLiveRegion({label, value, child})`

#### ScaffoldOverflowFade (_edge-fade gradient_)

**States:** default (fade applied), no-overflow (transparent)
**Visual:**
- Renders a `ShaderMask` with a linear gradient fading from transparent (center) to `backgroundColor` (edges).
- Configurable `fadeDirection` (horizontal, vertical, both) and `fadeExtent` (width of fade zone, default 24px).
- When the child does not overflow, the fade gradient is invisible (transparent colors at edges).

**Contract:** `ScaffoldOverflowFade({child, fadeDirection, fadeExtent, backgroundColor})`

#### ScaffoldScrollEdgeIndicator (_scroll-boundary marker_)

**States:** at-start, mid-scroll, at-end, mid-both
**Visual:**
- Renders thin hairlines (1px, `palette.borderSubtle`) at one or both edges of a scrollable when content extends beyond the viewport in that direction.
- Connects to a `ScrollController` to track position.
- Fades in/out with `ScaffoldMotion.durations.short` when the edge state changes.

**Contract:** `ScaffoldScrollEdgeIndicator({scrollController, edgeColor, edgeWidth})`

#### ScaffoldResponsiveVisibility (_breakpoint-aware show/hide_)

**States:** visible, hidden, replaced
**Visual:**
- Wraps child in a `LayoutBuilder` or uses `MediaQuery` to check against `ScaffoldBreakpoints`.
- Configurable `showAt` / `hideAt` with comparison operator (`>=`, `<=`, `<`, `>`).
- When hidden: renders `SizedBox.shrink()`. When `replacement` is provided and visible conditions not met: renders `replacement` widget instead.

**Contract:** `ScaffoldResponsiveVisibility({child, showAt, hideAt, operator, breakpoint, replacement})`
**Breakpoints:** small (760), tablet (1200), medium (1644), large (1920)

#### ScaffoldFormattedValue (_number/money/date display — template-generated_)

**States:** formatted, loading (null value), error (invalid format)
**Visual:**
- Template-generated per format variant (number, money, percentage, date, time, duration).
- Renders a `Text` widget using `textTheme.bodyLarge` with the formatted string.
- **Number:** "1,234" (group separators)
- **Money:** "$1,234.56" (currency symbol, group separators, decimal places)
- **Percentage:** "42.5%" (percent sign, configurable decimals)
- **Date:** "Aug 11, 2026" or "2026-08-11" (configurable locale/pattern)
- **Time:** "2:30 PM" (configurable 12h/24h)
- **Duration:** "01:23:45" (H:MM:SS or M:SS depending on magnitude)
- Loading state: `ScaffoldSkeleton` (consuming skeleton from Wave 1 in practice — zero-dep version uses a simple `Container` with shimmer color).
- Empty/null: renders `"--"` or the configured `nullPlaceholder`.

**Contract:** `ScaffoldFormattedValue({variant, value, locale, nullPlaceholder, style})`
**Accessibility:** Wraps result in `ScaffoldLiveRegion` for screen-reader announcement when value changes.

#### ScaffoldColorSwatch (_selectable/read-only color samples_)

**States:** default, selected, disabled
**Visual:**
- Renders a grid or row of 24px-diameter circles (configurable `dotSize`), each filled with a color from the `colors` list.
- Each swatch hit-tests at 48px (via `ScaffoldTouchTarget` wrapping each dot).
- **Selected:** `palette.lightGreenPrimary` ring (2px, `dimens.focusRingWidth`) around the selected swatch, inset by 2px.
- **Disabled:** `palette.disabledOverlayColor` at `dimens.disabledOverlayOpacity` over the disabled swatches.

**Contract:** `ScaffoldColorSwatch({colors, selectedIndex, onSelected, dotSize, disabled: false})`

### Wave 1: Single-Dependency Atoms (11 widgets)

#### ScaffoldBadge (_dot/count/icon/text indicator_)

**States:** empty (hidden), dot, count, icon, text, disabled
**Visual:**
- **Dot variant:** 8px circle (`palette.lightGreenPrimary` by default, configurable `badgeColor`). Positioned adjacent to child — does NOT include positioning; consumer uses `Stack` + `Positioned`.
- **Count variant:** Pill-shaped `Container` with `badgeColor` background, `borderRadiusPill`, containing a `Text` (count.toString(), `textTheme.labelSmall` in white). Width shrinks to fit; minimum 20px width. Max 2 digits ("99+") — configurable `maxDigits`.
- **Icon variant:** Small `Icon` (16px) inside a colored circle (24px diameter).
- **Text variant:** Custom label inside a pill.
- **Empty:** Renders `SizedBox.shrink()` when count is 0 or text is empty.
- **Disabled:** opacity 0.4.

**Contract:** `ScaffoldBadge({variant, count, text, icon, badgeColor, child, disabled: false})`

#### ScaffoldStatusIndicator (_generic status via color/shape/icon_)

**States:** success, warning, error, info, neutral, disabled
**Visual:**
- Renders a 12px circle (configurable `dotSize`) with a fill color mapped to the status variant:
  - **success:** `palette.statusSuccess`
  - **warning:** `palette.statusWarningText`
  - **error:** `palette.statusError`
  - **info:** `palette.blue500`
  - **neutral:** `palette.textSecondary`
- Optional `label` (rendered via `textTheme.labelMedium`) — visually hidden by default, exposed to screen readers via `Semantics(label:)`.
- **Disabled:** opacity 0.4.

**Contract:** `ScaffoldStatusIndicator({status, dotSize, label, disabled: false})`
**Accessibility:** `Semantics` role: `SemanticsRole.status`. `label` announced by screen readers.

#### ScaffoldSelectionIndicator (_radio/checkbox/toggle — template-generated_)

**States:** unchecked, checked, indeterminate (checkbox only), disabled
**Visual:**
- Template-generated per variant:
  - **Radio:** 20px circle outline, 12px filled inner circle when checked. Outline: `palette.textSecondary`, checked fill: `palette.lightGreenPrimary`.
  - **Checkbox:** 20px rounded-rect (2px radius), check-mark icon when checked, dash when indeterminate. Outline: `palette.textSecondary`, checked fill: `palette.lightGreenPrimary`, check: white.
  - **Toggle:** 40x24px pill track, 20px thumb circle. Track `palette.textSecondary` when off, `palette.lightGreenPrimary` when on. Thumb: `palette.surfaceElevated`.
- **Disabled:** opacity 0.4.
- All variants hit-test at 48px (via `ScaffoldTouchTarget`).

**Contract:** `ScaffoldSelectionIndicator({variant, value, onChanged, disabled: false, tristate: false})`
**Accessibility:** `Semantics` role: `SemanticsRole.radio` / `SemanticsRole.checkbox` / `SemanticsRole.switch`.

#### ScaffoldImagePlaceholder (_loading/missing/empty/failed — template-generated_)

**States:** loading, missing, empty, failed, loaded (renders child)
**Visual:**
- Template-generated per variant:
  - **Loading:** `ScaffoldSkeleton` (circular or rectangular, configurable aspect ratio)
  - **Missing:** Icon (`Icons.image_not_supported`, 48px, `palette.textSecondary`) centered on a `palette.deepBlueCardColor` surface with subtle border (`palette.borderSubtle`). Optional label below: "No image available" (consumer-provided string).
  - **Empty:** Icon (`Icons.photo_outlined`, 48px, `palette.textSecondary`) centered. Optional consumer label.
  - **Failed:** Icon (`Icons.broken_image`, 48px, `palette.statusError`) centered. Optional consumer label.
- **Loaded:** Renders `child` normally (placeholders are a fallback, not a permanent wrapper).

**Contract:** `ScaffoldImagePlaceholder({variant, child, aspectRatio, label, onRetry})`
**Accessibility:** Screen-reader label from state (`"Loading image"`, `"Image failed to load"`, `"No image"`).

#### ScaffoldSkeleton (_animated placeholder_)

**States:** loading, loaded (hidden)
**Visual:**
- Renders a rounded-rect `Container` with `palette.skeletonBaseColor` fill and `dimens.skeletonCornerRadius` (4px).
- Animated shimmer: a `LinearGradient` sweep across the skeleton at `ScaffoldMotion.durations.medium` interval using `ScaffoldMotion.curves.standard`. Shimmer color: `palette.skeletonShimmerColor`.
- **Reduced motion:** When `ScaffoldMotion.of(context).reducedMotion == true`, the shimmer is replaced by a static pulse (opacity oscillation from 0.6 to 1.0) — no horizontal motion.
- Configurable `width`, `height`, `borderRadius` (override skeleton corner radius).

**Contract:** `ScaffoldSkeleton({width, height, borderRadius, child: null})`
**Accessibility:** `ExcludeSemantics(true)` — no screen-reader announcement for skeleton animations.

#### ScaffoldAnimatedDisplay (_fade/pulse/scale/slide/rotate/shake/bounce — template-generated_)

**States:** enter, exit, active, idle
**Visual:**
- Template-generated per animation variant:
  - **Fade:** `AnimatedOpacity` — 0.0 to 1.0 over `ScaffoldMotion.durations.medium`.
  - **Pulse:** Repeated scale 1.0 to 1.05 and back over `ScaffoldMotion.durations.short`.
  - **Scale:** `AnimatedScale` — 0.8 to 1.0 on enter, 1.0 to 0.8 on exit.
  - **Slide:** `AnimatedSlide` — from offset (configurable direction) to zero.
  - **Rotate:** `RotationTransition` — configurable turns.
  - **Shake:** `AnimatedBuilder` with sine-wave horizontal offset — configurable intensity.
  - **Bounce:** `AnimatedBuilder` with damped vertical oscillation — configurable intensity.
- All respect `ScaffoldMotion.of(context).reducedMotion`: fade becomes instant opacity toggle; all motion-based animations (scale, slide, rotate, shake, bounce) become simple fade-in.
- `trigger` parameter (optional) — when non-null, animation plays on trigger change; when null, animation plays on mount.

**Contract:** `ScaffoldAnimatedDisplay({variant, child, duration, curve, trigger, intensity})`

#### ScaffoldPressable (_pressed/hovered/focused/disabled state wrapper_)

**States:** idle, hovered, pressed, focused, disabled
**Visual:**
- Wraps `child` in an `InkWell`-like surface that applies state layers using Material 3 conventions:
  - **Hovered:** `palette.textPrimary` at 8% opacity overlay.
  - **Pressed:** `palette.textPrimary` at 12% opacity overlay (splash).
  - **Focused:** `ScaffoldFocusOutline` ring.
  - **Disabled:** `ScaffoldDisabledOverlay` at `dimens.disabledOverlayOpacity`.
- Composes `ScaffoldTouchTarget` internally to guarantee 48x48 hit area.
- Exposes `onPressed`, `onLongPress`, `onHoverChanged`, `focusNode`.
- Animation: hover overlay uses `ScaffoldMotion.durations.short` fade; press splash resolves at `ScaffoldMotion.durations.medium`.

**Contract:** `ScaffoldPressable({child, onPressed, onLongPress, onHoverChanged, focusNode, disabled: false})`
**Accessibility:** `Semantics` role: `SemanticsRole.button`. Keyboard: Enter/Space fire `onPressed`.

#### ScaffoldDisabledOverlay (_interaction blocker with visual dim_)

**States:** enabled (transparent), disabled (dimmed), disabled-with-tooltip (dimmed + reason)
**Visual:**
- Renders a semi-transparent overlay (`palette.disabledOverlayColor` at `dimens.disabledOverlayOpacity`) over the `child`.
- Uses `IgnorePointer` to block all interaction.
- Optional `reason` string: shown in a tooltip on long-press or hover (accessible: `Semantics(tooltip: reason)`).
- **Enabled state:** Renders `child` without overlay — zero-opacity cost.

**Contract:** `ScaffoldDisabledOverlay({child, disabled, reason})`

#### ScaffoldDragHandle (_reorder grip_)

**States:** idle, dragged
**Visual:**
- Renders a 24px-wide horizontal strip (`dimens.dragHandleSize`) of 3 parallel lines (2px height each, `palette.textSecondary` at 60% opacity), centered vertically.
- Wraps in `ScaffoldTouchTarget` for 48px touch area.
- **Dragged:** lines brighten to `palette.lightGreenPrimary` at 80% opacity (feedback from parent `ScaffoldDraggable` via callback).

**Contract:** `ScaffoldDragHandle({color, size})`
**Accessibility:** `Semantics` role: `SemanticsRole.moveHandle`. Label: "Drag to reorder".

#### ScaffoldResizeHandle (_horizontal/vertical/corner resize grip_)

**States:** idle, dragged
**Visual:**
- Renders an L-shaped corner or horizontal/vertical stripe (2px, `palette.textSecondary` at 60% opacity), depending on `direction` (horizontal, vertical, both/corner).
- Wraps in `ScaffoldTouchTarget` for 48px interactive zone.
- **Dragged:** lines brighten to `palette.lightGreenPrimary` at 80% opacity.

**Contract:** `ScaffoldResizeHandle({direction, color, size})`

#### ScaffoldNumericInput (_bounded/precision/step number input_)

**States:** default, focused, disabled, error
**Visual:**
- Renders a horizontal layout: decrement button (-), value display, increment button (+).
- Buttons: 48x48px (via `ScaffoldTouchTarget`), icon: `Icons.remove` / `Icons.add`, color: `palette.textPrimary` (idle), `palette.lightGreenPrimary` (pressed).
- Value display: `Text` with `textTheme.bodyLarge`, centered, minimum 64px width.
- **Focused:** `ScaffoldFocusOutline` around the entire input.
- **Disabled:** `ScaffoldDisabledOverlay` over the entire control.
- **Error:** `palette.statusError` tint on value display text, error border (`palette.statusError` at 50% opacity, 1px).
- Configurable `min`, `max`, `step`, `decimalPlaces`, `prefix`, `suffix`.

**Contract:** `ScaffoldNumericInput({value, onChanged, min, max, step, decimalPlaces, prefix, suffix, disabled: false, error: null})`
**Accessibility:** `Semantics` role: `SemanticsRole.spinButton`. Buttons labeled "Increment" / "Decrement". Value announced via `ScaffoldLiveRegion`.

### Wave 2: Multi-Dependency Atoms (4 widgets)

#### ScaffoldSelectableSurface (_selected/focused/pressed/disabled surface_)

**States:** unselected, selected, focused, pressed, disabled
**Visual:**
- Composes `ScaffoldSurface` + `ScaffoldPressable`:
  - **Unselected:** Default surface color (`palette.deepBlueCardColor`).
  - **Selected:** `palette.lightGreenPrimary` at 12% opacity overlay, 1px `palette.lightGreenPrimary` border.
  - **Focused:** `ScaffoldFocusOutline` ring (inherited from `ScaffoldPressable` focus state).
  - **Pressed:** Pressed state layer from `ScaffoldPressable`.
  - **Disabled:** `ScaffoldDisabledOverlay`.
- Transitions between states use `ScaffoldMotion.durations.medium` with `ScaffoldMotion.curves.standard`.

**Contract:** `ScaffoldSelectableSurface({child, selected, onTap, onLongPress, disabled: false})`

#### ScaffoldDraggable (_drag wrapper with feedback/preview_)

**States:** idle, dragging, drag-accepted, drag-rejected
**Visual:**
- Wraps `child` in a Flutter `LongPressDraggable`:
  - **Idle:** Normal child rendering.
  - **Dragging:** `feedback` widget (default: slightly scaled-up child at 1.05x with `ScaffoldElevation.card` shadow and `palette.dragFeedbackBackground`). Original child fades to 40% opacity.
  - Uses `ScaffoldMotion.durations.short` for elevation transition.
- Composes `ScaffoldPressable` for long-press detection and `ScaffoldDragHandle` (optional — consumer can provide their own handle).

**Contract:** `ScaffoldDraggable({child, data, feedback, childWhenDragging, dragHandle, onDragStarted, onDragEnd, onDraggableCanceled})`

#### ScaffoldDropTarget (_drop zone with idle/accepted/rejected/dropped states_)

**States:** idle, over (accepted), over (rejected), dropped
**Visual:**
- Composes `ScaffoldSurface` + `ScaffoldStatusIndicator`:
  - **Idle:** Default surface with dashed 1px border (`palette.borderSubtle`).
  - **Over (accepted):** `palette.dropZoneHighlight` background tint, solid 1px `palette.lightGreenPrimary` border. Optional icon: `Icons.add` (`palette.lightGreenPrimary`).
  - **Over (rejected):** `palette.dropZoneRejected` background tint, solid 1px `palette.statusError` border. Optional icon: `Icons.block` (`palette.statusError`).
  - **Dropped:** Accepted tint for 500ms, then returns to idle.
- Transitions: `ScaffoldMotion.durations.medium` with `ScaffoldMotion.curves.standard`.

**Contract:** `ScaffoldDropTarget({child, onAccept, onReject, acceptType, acceptCondition})`
**Accessibility:** `Semantics` label: "Drop zone. {state-specific label}".

#### ScaffoldFileInputSurface (_file select/drop surface with validation_)

**States:** idle, file-selected (valid), file-selected (invalid), dragging-over, disabled
**Visual:**
- Composes `ScaffoldSurface` + `ScaffoldDropTarget` + `ScaffoldStatusIndicator`:
  - **Idle:** Surface with dashed border, centered icon (`Icons.upload_file`, 48px, `palette.textSecondary`) and label "Choose a file or drag here" (consumer string — not hardcoded).
  - **File-selected (valid):** Filled border (`palette.statusSuccess`), success icon (`Icons.check_circle`, `palette.statusSuccess`), and file name text.
  - **File-selected (invalid):** Filled border (`palette.statusError`), error icon (`Icons.error`, `palette.statusError`), and validation message text.
  - **Dragging-over:** `ScaffoldDropTarget` over state (see above).
  - **Disabled:** `ScaffoldDisabledOverlay`.
- Exposes `onFileSelected(File file)`, `validate(File file)? → String?` (returns null for valid, error string for invalid).

**Contract:** `ScaffoldFileInputSurface({onFileSelected, validate, acceptTypes, maxSize, disabled: false})`

### Wave 3: Template-Generated Composites (3 widgets)

These ship from existing `templates/components/` Jinja2 templates (`card.dart.jinja2`, `state.dart.jinja2`, `search_bar.dart.jinja2`). The templates encode which atoms compose for each variant; the atoms themselves are ingredients.

#### ScaffoldCard (_elevated/outlined/filled variant_)

**States:** idle, pressed (when interactive), disabled
**Visual:**
- Template-generated. Composes `ScaffoldSurface` + `ScaffoldPressable` (when `onTap` is non-null).
- **Elevated variant:** `elevation: 4` with `ScaffoldElevation.card` shadow. Background: `palette.deepBlueCardColor`.
- **Outlined variant:** `elevation: 0`, 1px `palette.borderSubtle` border. Background: transparent.
- **Filled variant:** `elevation: 0`, no border. Background: `palette.surfaceElevated`.
- Three slot zones managed by the template:
  - `header`: Widget (rendered above body, padded)
  - `body`: Widget (main content)
  - `actions`: List<Widget> (rendered in a `Row` at bottom-right, spaced with `dimens.space4`)

**Contract:** `ScaffoldCard({variant, header, body, actions, onTap, disabled: false})`

#### ScaffoldStateView (_loading/empty/error/unavailable/success states_)

**States:** loading, empty, error, unavailable, success
**Visual:**
- Template-generated. Composes different atom sets per variant:
  - **Loading:** Centered `ScaffoldSkeleton` (configurable width/height) + optional `ScaffoldStatusIndicator(loading)`.
  - **Empty:** Centered icon (configurable, default `Icons.inbox_outlined`, 64px, `palette.textSecondary`) + headline text + body text + optional action button. All consumer-supplied content.
  - **Error:** Centered icon (default `Icons.error_outline`, 64px, `palette.statusError`) + error headline + error message + retry button (`ScaffoldPressable`).
  - **Unavailable:** Centered icon (default `Icons.cloud_off`, 64px, `palette.textSecondary`) + headline + message.
  - **Success:** Centered icon (default `Icons.check_circle`, 64px, `palette.statusSuccess`) + headline + message + optional action.
- All text uses `textTheme.headlineSmall` (headline) and `textTheme.bodyLarge` (message).
- `onRetry` callback on error/unavailable states re-triggers the loading state.

**Contract:** `ScaffoldStateView({state, loadingWidget, emptyIcon, emptyHeadline, emptyBody, emptyAction, errorHeadline, errorBody, onRetry, unavailableHeadline, unavailableBody, successIcon, successHeadline, successBody, successAction})`

#### ScaffoldSearchBar (_pill-shaped search with clear/loading/filtering_)

**States:** idle, focused, loading, has-query, showing-results
**Visual:**
- Template-generated. Composes `ScaffoldSurface` + `ScaffoldPressable` + `ScaffoldStatusIndicator`.
- Renders as a pill-shaped (`dimens.radiusPill`) surface with:
  - Leading `Icons.search` icon (24px, `palette.textSecondary`).
  - `TextField` with no border, `textTheme.bodyLarge`, hint: "Search..." (configurable `hintText`).
  - Trailing row: clear button (`Icons.close`, visible when query non-empty) + loading indicator (`ScaffoldStatusIndicator(loading)` when `isLoading`) + filter icon (`Icons.filter_list`, when `onFilterTap` is non-null) + result count badge (`ScaffoldBadge({count: resultCount})`).
- **Focused:** `ScaffoldFocusOutline` ring.
- **Loading:** clear button hidden, loading indicator shown.
- Filter pill toggles between active/inactive appearance using `palette.lightGreenPrimary` tint.

**Contract:** `ScaffoldSearchBar({query, onQueryChanged, isLoading, onClear, onFilterTap, isFiltered, resultCount, hintText, onSubmitted})`
**Accessibility:** `Semantics` role: `SemanticsRole.search`. Announce result count changes via `ScaffoldLiveRegion`.

## Interaction Patterns

### Press / Hover / Focus / Drag

All interactive atoms follow this unified interaction model:

| Interaction | Visual Feedback | Duration | Curve |
|-------------|----------------|----------|-------|
| Hover enter | `palette.textPrimary` at 8% opacity state layer | 150ms (`short`) | `easeInOut` (`standard`) |
| Press down | `palette.textPrimary` at 12% opacity state layer | 150ms | `easeInOut` |
| Press release | State layer removes (fade to idle) | 300ms (`medium`) | `easeOut` (`decelerate`) |
| Focus | `ScaffoldFocusOutline` ring appears | 0ms (instant) | None |
| Drag start | Elevation pop (shadow appears), feedback widget scales to 1.05 | 150ms | `easeOut` |
| Drag end | Elevation drop, feedback widget fades | 300ms | `easeInOut` |
| Drop zone enter | Background tint fades in | 150ms | `easeInOut` |
| Drop zone exit | Background tint fades out | 300ms | `easeOut` |

### Animation Contract (via ScaffoldMotion)

Every animation in every atom MUST respect `ScaffoldMotion.of(context).reducedMotion`:
- **When `reducedMotion` is false:** Normal animation with durations and curves from `ScaffoldMotion` utility class.
- **When `reducedMotion` is true:** All motion animations (scale, slide, rotate, shake, bounce, path) become simple fade-in/opacity transitions. Scale/slide/rotate transitions set duration to `Duration.zero` and use `FadeTransition` instead. Shimmer skeleton becomes static pulse (opacity only — no horizontal sweep).
- **Focus ring:** Unaffected by reduced motion (it is instant, not animated).
- **State layer transitions:** Fade-only (already opacity), keep at `ScaffoldMotion.durations.short`.

### Disabled State Contract

Any atom with a `disabled` parameter must:
1. Apply `ScaffoldDisabledOverlay` (or equivalent internal opacity/dim)
2. Block ALL interaction (`onPressed`, `onTap`, `onLongPress`, drag, focus)
3. Set `Semantics` property: `excludeSemantics: false` with `onTapHint: null`
4. Maintain layout footprint — disabled widgets occupy the same space as enabled ones
5. Visual dim: `palette.disabledOverlayColor` at `dimens.disabledOverlayOpacity`

## Responsive Behavior

Atoms are **responsive-neutral** by design. They do NOT contain breakpoint logic, `MediaQuery` calls, or layout decisions — consumers handle layout and responsiveness. The sole exception is `ScaffoldResponsiveVisibility`, which is the atom that implements breakpoint-aware show/hide.

| Atom | Responsive Behavior |
|------|-------------------|
| `ScaffoldResponsiveVisibility` | The ONLY atom with breakpoint awareness. Uses `ScaffoldBreakpoints` to show/hide/replace at width thresholds. |
| All other atoms | No breakpoint logic. Atoms take `width`/`height`/`constraints` parameters as configurable values; the consumer's layout (Row, Column, GridView, etc.) controls the responsive behavior. |
| `ScaffoldSurface` | Adapts to `constraints` given by parent layout — no intrinsic responsive logic. |
| `ScaffoldCard` | Width/height from parent layout. Aspect-neutral. |
| `ScaffoldSearchBar` | Expands to fill parent width (default `Expanded`). Minimum width: 200px. |

**Breakpoints (reference — from `ScaffoldBreakpoints`):**

| Name | Width | Consumer Usage Examples |
|------|-------|------------------------|
| `small` | `<= 760px` | Mobile portrait/landscape |
| `tablet` | `<= 1200px` | Tablet, narrow desktop |
| `medium` | `<= 1644px` | Standard desktop |
| `large` | `<= 1920px` | Wide desktop |

Atoms that accept an explicit `size` parameter (e.g., `ScaffoldSurface`, `ScaffoldSkeleton`) default to parent constraints when not specified.

All 28 atoms + ScaffoldMotion must satisfy this accessibility contract:

### Semantics

| Atom | Semantic Role | Semantic Properties | Notes |
|------|--------------|-------------------|-------|
| `ScaffoldTouchTarget` | `container` | None | Ensures screen readers identify the touch zone |
| `ScaffoldFocusOutline` | None (visual-only) | None | Semantics handled by the focused widget, not the outline |
| `ScaffoldBadge` | `status` | `label`: badge text/count | Count version labeled "{count} items" |
| `ScaffoldStatusIndicator` | `status` | `label`: consumer-provided status string | |

| `ScaffoldSelectableSurface` | `button` | `selected`, `enabled` | |
| `ScaffoldDragHandle` | `moveHandle` | `label`: "Drag to reorder" | |
| `ScaffoldResizeHandle` | `adjustHandle` | `label`: "Drag to resize" | |
| `ScaffoldNumericInput` | `spinButton` | `value`, `increasedValue`, `decreasedValue` | |

| `ScaffoldStateView` | `status` | `label`: empty/error/loading message | |
| `ScaffoldAnimatedDisplay` | None | `ExcludeSemantics` when animating | Animations are visual; content underneath provides semantics |

### Live Region

Atoms that report changing values use `ScaffoldLiveRegion`:
- `ScaffoldNumericInput` — announces value changes ("5", "6", "7" on increment)
- `ScaffoldFormattedValue` — announces formatted value changes
- `ScaffoldStatusIndicator` — announces status changes ("Connected", "Disconnected")
- `ScaffoldSearchBar` — announces result count changes ("5 results found")

### Focus Management

- Keyboard-navigable atoms (`ScaffoldPressable`, `ScaffoldSelectableSurface`, `ScaffoldDraggable`, `ScaffoldDropTarget`, `ScaffoldNumericInput`) participate in focus order (`FocusTraversalGroup`).
- All keyboard-activatable atoms respond to `Enter` and `Space` keys.
- Focus outline (`ScaffoldFocusOutline`) must be visible when `MediaQuery.of(context).accessibleNavigation == true`, even without physical keyboard focus — this ensures TalkBack/VoiceOver users see focus rings.

### Touch Targets

Hard minimum 48x48px for every interactive element. Enforced by:
- `ScaffoldTouchTarget` wrapping smaller children with transparent padding
- `dimens.minTouchTarget` (48) and `dimens.touchTargetPadding` (12) tokens used by all interactive atoms

### Reduced Motion

All animations respect `ScaffoldMotion.of(context).reducedMotion` — see Animation Contract above.

## Copywriting Contract

Atoms are **generic primitives** with NO hardcoded copy. The 25 atoms in Waves 0-2 do not contain user-facing strings — all labels, text, hints, and messages come from the consumer app. The 3 template-generated composites in Wave 3 have CONSUMER-CONFIGURABLE strings, not hardcoded defaults:

### Wave 3 Composite Defaults (Consumer-Overridable)

| Element | Template Default | Consumer Override |
|---------|-----------------|-------------------|
| ScaffoldSearchBar hintText | `"Search..."` | `hintText` parameter |
| ScaffoldSearchBar resultCount label | None (just badge number) | Consumer owns the label |
| ScaffoldStateView empty headline | `"Nothing here"` | `emptyHeadline` parameter |
| ScaffoldStateView empty body | `"No items to display."` | `emptyBody` parameter |
| ScaffoldStateView error headline | `"Something went wrong"` | `errorHeadline` parameter |
| ScaffoldStateView error body | `"Please try again."` | `errorBody` parameter |
| ScaffoldStateView unavailable headline | `"Service unavailable"` | `unavailableHeadline` parameter |
| ScaffoldStateView unavailable body | `"Please try again later."` | `unavailableBody` parameter |
| ScaffoldStateView success headline | `"Done!"` | `successHeadline` parameter |
| ScaffoldStateView retry button | `"Retry"` | No text override; consumer provides the button widget itself via `successAction`/`emptyAction` |
| ScaffoldFileInputSurface idle label | `"Choose a file or drag here"` | Consumer passes via `idleLabel` parameter |

### Atom-Level Copy Rules

- `ScaffoldFormattedValue`: Format strings come from the consumer's locale and pattern configuration. The atom ships with sensible defaults (number: `#,###.##`, money: `$#,###.00`, date: `MMM d, yyyy`, time: `h:mm a`, duration: `H:mm:ss`). All overridable.
- `ScaffoldBadge`: "99+" truncation is the only string-adjacent logic — pure numeric, no localization.
- Destructive confirmations: NOT APPLICABLE to atoms. Destructive confirmation dialogs are consumer-tier logic (built by composing `ScaffoldSurface` + `ScaffoldPressable` + consumer copy).
- Error messages: Atoms display error via visual state (red tint, error border). Error COPY comes from the consumer.
