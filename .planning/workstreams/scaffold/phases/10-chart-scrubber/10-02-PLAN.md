<objective>
Isolate fl_chart behind a scaffold-neutral renderer (D-02). This support part is the ONLY file in the scaffold that imports `package:fl_chart` — base atoms in `lib/components/` stay fl_chart-free. The renderer takes a fully-resolved configuration (spots, palette, textTheme, dimens, geometry results, scrub callbacks) and returns a `LineChart` widget wired per the UI-Spec and D-05/D-06/D-07.

Purpose: Locks the fl_chart dependency into a single seam so (a) base atoms don't pay for it, (b) consumers wanting a different chart engine replace one file, and (c) all fl_chart API surface (LineChart, LineChartData, LineTouchData, FlGridData, FlTitlesData, FlDotCirclePainter) is concentrated in one auditable location.

Output: One library file (`lib/utils/scaffold_chart_renderer.dart`), one widget-test file, one pubspec edit.
</objective>

Signature: `Widget buildScaffoldLineChart({required List<ChartPoint> spots, required double plotHeight, required double plotWidth, required Color lineColor, required Color borderControl, required Color borderSubtle, required Color textSecondary, required TextStyle axisLabelStyle, required bool reducedMotion, ValueChanged<int>? onSpotTouched, double? viewMinX, double? viewMaxX, double? minX, double? maxX})` — returns a `LineChart` (framed scheme B when `chartUsesFrame(plotHeight)`, axis-free scheme A otherwise).

Why palette pieces are passed individually (not as a `ScaffoldPalette`): the support part stays scaffold-theme-agnostic — it takes Color/TextStyle values. The calling atom (Plan 03) resolves them from `context.palette` / `context.textTheme`. This keeps the renderer unit-testable without a Theme wrapper.

Behavioral contract (from D-05, D-06, D-07 + UI-Spec):
- `isCurved: false`, `barWidth: 2`, `dotData: FlDotData(show: false)`
- Below-bar gradient: `LinearGradient(colors: [lineColor at alpha 0.26, lineColor at alpha 0], begin: topCenter, end: bottomCenter, stops: [0.0, kChartFillFadeStop])`
- Y bounds: caller computes `chartYBounds(spots, viewMinX:, viewMaxX:)` in the atom; renderer takes minY/maxY as already-resolved inputs. Renderer NEVER recomputes them. Wait — simpler: renderer accepts `(double, double) yBounds` parameter directly so atom owns the visible-window rule. Add `required (double, double) yBounds` parameter; drop minY/maxY from the parameter list.
- Grid (framed only): `FlGridData(show: true, drawVerticalLine: false, horizontalInterval: step, getDrawingHorizontalLine: → FlLine(color: borderSubtle at alpha 0.06, strokeWidth: 1))` where `step = chartTickStep(yBounds.$1, yBounds.$2, chartYTickCount(plotHeight - kChartTimeRowHeight)).$2`
- Grid (axis-free): `FlGridData(show: false)`
- Border: ALWAYS `FlBorderData(show: false)`
- Titles (framed): `rightTitles` only with `reservedSize: kChartAxisGutter`, `interval: step`, `minIncluded: false`, `maxIncluded: false`, `getTitlesWidget: → SideTitleWidget(meta:, space: 8, child: Text(chartAxisLabel(value, step), style: axisLabelStyle))`. `leftTitles`/`topTitles`/`bottomTitles` are `AxisTitles(sideTitles: SideTitles(showTitles: false))` — bottom titles are NEVER used (D-06); the atom renders X labels as a separate Row.
- Titles (axis-free): all four sides `showTitles: false`
- Touch: `LineTouchData(enabled: onSpotTouched != null, handleBuiltInTouches: true, touchCallback: (event, response) { final spot = response?.lineBarSpots?.firstOrNull; if (spot != null) onSpotTouched?.call(spot.spotIndex); }, getTouchLineStart: → yBounds.$1, getTouchLineEnd: → yBounds.$2, getTouchedSpotIndicator: → TouchedSpotIndicatorData(FlLine(color: borderControl, strokeWidth: 1), FlDotData(getDotPainter: → FlDotCirclePainter(radius: 5, color: lineColor, strokeWidth: 4, strokeColor: lineColor at alpha 0.26))))`
- Tooltip: ALWAYS suppressed — `LineTouchTooltipData(getTooltipColor: → Colors.transparent, tooltipBorder: BorderSide.none, tooltipPadding: EdgeInsets.zero, getTooltipItems: (spots) → spots.map((_) => null).toList())`
- Clip: `clipData: FlClipData.all()`
- reducedMotion: when true, the renderer must pass `LineChartData(..., )` such that fl_chart's implicit animations are off. fl_chart 1.2.0 does not animate by default when given static data — no explicit swapAnimation needed. Document this in the function comment and DO NOT add animation code.
