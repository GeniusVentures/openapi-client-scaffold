## Spacing Scale

Reuse the existing `ScaffoldDimens` scale (2px base step, named by step index).
**Do NOT introduce new spacing tokens.** Phase 8 widgets consume only the existing steps.

| Token | Value | Phase 8 Usage |
|-------|-------|---------------|
| `space2` | 4px | Chip internal icon↔text gap; badge-to-label gap inside `ScaffoldComposer` action row |
| `space3` | 6px | (rare) Tight inline gap inside a chip when both icon + status dot present |
| `space4` | 8px | Default chip horizontal internal padding; disclosure header↔chevron gap; composer badge-row gap |
| `space6` | 12px | Chip vertical internal padding; disclosure body indent; composer action-button separation |
| `space8` | 16px | Default chip-group inter-chip spacing; disclosure item vertical rhythm; composer text-field↔action-row separation; DataTable cell padding (matches existing template) |
| `space12` | 24px | Section-level padding inside `ScaffoldTraceList` between disclosure groups; composer outer padding |

**Exceptions:**
- DataTable cell padding stays at the existing `EdgeInsets.symmetric(horizontal: 16.0, vertical: 8.0)` — preserved by WIDG-43 so custom cells align with built-in string cells.
- Chip min-height is governed by `minTouchTarget` (48px) via `ScaffoldTouchTarget`, not by a new token.
- Composer action button slots inherit `ScaffoldTouchTarget` 48x48 minimum.

**Multiples-of-4 audit:** all values above (4, 8, 12, 16, 24) are multiples of 4 except `space3` (6px) which is reserved for the rare icon+status-dot chip case and matches the existing dimens scale.

## Typography

Atoms consume the host `TextTheme` slots — no new font sizes, no font wrappers.
Use exactly these four slots; do not introduce additional ones.

| Role | M3 Slot | Weight | Phase 8 Usage |
|------|---------|--------|---------------|
| Body | `textTheme.bodyMedium` | inherited (default 400) | Composer text field, disclosure body content, custom cellBuilder default text when consumer does not override |
| Label | `textTheme.labelMedium` | inherited (default 500) | `ScaffoldChip` text label, disclosure header title, composer badge labels |
| Heading | `textTheme.titleSmall` | inherited (default 500) | `ScaffoldTraceList` group headers, disclosure header when emphasized, DataTable column header (matches existing template: `labelLarge` w600) |
| Display | not used in Phase 8 | — | — |

**Table header alignment rule (WIDG-43 contract):**
- Custom `cellBuilder` widgets inherit `textTheme.bodyMedium` styling by default and align left, matching the built-in string-cell rendering.
- Sort-header alignment matches the existing template: `Expanded` column with left-aligned `labelLarge` w600 text. Custom cells do NOT change header behavior.

**Line height:** inherited from M3 defaults (1.4 for body, 1.3 for label). Do NOT override.

## Color

Reuse the existing `ScaffoldPalette` — do NOT introduce new tokens. Phase 8 ships the missing light-palette coverage so every widget renders correctly under both `defaultPalette` (dark) and `lightPalette` (light) without consumer overrides.

| Role | Token | Dark (existing) | Light (existing — verify + extend) | Phase 8 Usage |
|------|-------|-----------------|------------------------------------|---------------|
| Dominant 60% | `palette.surfaceElevated` | `#0C0E14` | `#FFFFFF` | ChipGroup background, disclosure surface, composer container fill |
| Secondary 30% | `palette.deepBlueCardColor` | `#0A121F` | `#FFFFFF` (light) | Chip fill, disclosure header fill, trace-list row fill, table header |
| Accent 10% | `palette.lightGreenPrimary` | `#00EAAE` | `#00EAAE` (shared) | **Reserved list below** |
| Destructive | `palette.statusError` | `#FF4D4D` | `#D13438` | Drop-reject states in composer attachment slot; disclosure error state |

**Accent (`lightGreenPrimary`) reserved for — exclusive list:**
1. Focus ring (`focusRingColor` — already locked)
2. Selected-chip indicator (when `ScaffoldChip` is in selected state)
3. Disclosure chevron in expanded + active state
4. Composer primary-action slot icon tint when armed
5. DataTable sort-active header underline (matches existing template convention)

**Accent is NEVER used for:** body text, surface fills, generic borders, chip default fill.

**Status colors (existing — do not change):**
- `statusSuccess`, `statusError`, `statusWarningText` — used by `ScaffoldStatusIndicator` inside chip status slot, composer badge, trace-list row status.
- `blue500` — informational status (existing `StatusVariant.info`).

**Light palette coverage gap closure (WIDG-46):**
- `ScaffoldPalette.lightPalette` already exists in source. Phase 8 verifies EVERY widget (existing v1.1 + new v1.2) renders correctly under a default `ThemeData.light()` registered with `ScaffoldPalette.lightPalette` — no consumer override.
- Any widget that hardcodes a dark-only color (e.g. `Colors.white` for badge text) must use a palette token that has both dark and light values, OR a neutral token whose contrast holds on both surfaces.
- Specifically: `ScaffoldBadge` text on `lightGreenPrimary` currently uses `Colors.white` — under light palette this must remain readable (verify or switch to `textPrimary` if needed).

## Copywriting Contract

Atoms are domain-agnostic (locked constraint). Atoms ship with NO hardcoded copy beyond the structural defaults below; consumers provide all visible strings via parameters.

| Element | Copy | Owner |
|---------|------|-------|
| Primary CTA | not applicable — atoms expose slots, consumers supply labels | consumer |
| Empty state (ScaffoldChipGroup) | No chips — group renders zero-size `SizedBox.shrink()` | atom behavior |
| Empty state (ScaffoldTraceList) | No items — renders zero-size `SizedBox.shrink()` | atom behavior |
| Empty state (ScaffoldComposer) | Consumer supplies `hintText` for the text field | consumer |
| Error state (ScaffoldComposer) | Consumer supplies via decoration; atom does not hardcode | consumer |
| DataTable empty | "No items to display" (existing template — do NOT change) | atom (locked) |
| DataTable load failure toast | "Table load failed" (existing template — do NOT change) | atom (locked) |
| Destructive confirmation | not applicable — no destructive atoms in Phase 8 | — |
| Semantics labels (a11y) | `ScaffoldChip` requires `semanticLabel` when icon-only; `ScaffoldDisclosure` announces "expanded" / "collapsed" state; `ScaffoldComposer` text field uses M3 default text-field semantics | atom contract |

**Rule:** Any user-visible string in a Phase 8 widget MUST be a required-or-optional constructor parameter. Atoms ship with empty/zero defaults, never with placeholder English text (except the pre-existing DataTable strings above which are part of the shipped template).

## Widget-Specific Visual Contracts

### ScaffoldChip (WIDG-40)

| Property | Contract |
|----------|----------|
| Shape | Pill — `BorderRadius.circular(dimens.radiusPill)` (48px) |
| Fill | Default: `palette.deepBlueCardColor`. Selected: same fill + 2px `palette.lightGreenPrimary` border (NOT a fill change — preserves 60/30/10). |
| Padding | `EdgeInsets.symmetric(horizontal: dimens.space4, vertical: dimens.space3)` — 8h x 6v |
| Internal gap | `dimens.space2` (4px) between leading icon, label, status indicator, trailing slot |
| Min size | `ScaffoldTouchTarget` enforced (48x48 hit area; visual may be smaller) |
| Press behavior | `ScaffoldPressable` — inherits hover (8% `textPrimary`), press (12% `textPrimary`), focus ring, disabled overlay |
| Status slot | Optional `ScaffoldStatusIndicator` — positioned trailing, after label |
| Leading slot | Optional icon (16px) or avatar-sized widget |
| Disabled | `ScaffoldDisabledOverlay` at `dimens.disabledOverlayOpacity` (0.40) |
| Typography | `textTheme.labelMedium` |

### ScaffoldChipGroup (WIDG-40)

| Property | Contract |
|----------|----------|
| Layout | `Wrap` with `spacing: dimens.space8` (16px), `runSpacing: dimens.space4` (8px) |
| Selection | Reports `Set<int>` (or `Set<T>`) of selected indices via `onSelectionChanged` |
| Modes | Single-select (radio semantics) or multi-select (checkbox semantics) — parameter-driven |
| Empty | `SizedBox.shrink()` — group takes zero space when empty |

### ScaffoldDisclosure (WIDG-41)

| Property | Contract |
|----------|----------|
| Header row | `ScaffoldPressable` wrapping a `Row`: [title `Expanded`, chevron `Icon`] with `dimens.space4` gap |
| Chevron | 24px, rotates 0°→90° (or 180°) on expand using `ScaffoldMotionDurations.short` + `ScaffoldMotionCurves.standard` |
| Chevron color | `palette.textSecondary` (default); `palette.lightGreenPrimary` when expanded AND `highlightWhenExpanded: true` |
| Body indent | `EdgeInsets.only(left: dimens.space6, top: dimens.space4)` — 12px left, 8px top |
| Body animation | `AnimatedSize` with `ScaffoldMotionDurations.medium`, `ScaffoldMotionCurves.standard` |
| Semantics | `Semantics(expanded: bool, label: title)`; announces state change |
| Border | Optional `palette.borderSubtle` bottom border between header and body when expanded |

### ScaffoldTraceList (WIDG-41)

| Property | Contract |
|----------|----------|
| Layout | `Column` of `ScaffoldDisclosure` items with `dimens.space8` (16px) vertical separation |
| Group header | Optional `textTheme.titleSmall` header with `dimens.space12` (24px) top padding |
| Ordered trace | Accepts `List<TraceItem>` (label, body, optional status) — renders each as a disclosure row |
| Status slot | Optional `ScaffoldStatusIndicator` per item, leading, before title |
| Empty | `SizedBox.shrink()` |

### ScaffoldComposer (WIDG-42)

| Property | Contract |
|----------|----------|
| Surface | `ScaffoldSurface` (or equivalent) with `palette.surfaceElevated` fill, `palette.borderSubtle` 1px border, `dimens.radiusMd` (12px) corner radius |
| Layout | `Column` with `dimens.space4` (8px) vertical gap between rows: [badge-row?, text-field-row, action-row?] |
| Text field | M3 `TextField` (or `TextFormField`) with `decoration: InputDecoration(border: InputBorder.none, hintText: consumer-supplied)` — typography `textTheme.bodyMedium` |
| Action row | `Row` with `mainAxisAlignment: MainAxisAlignment.end`, `dimens.space4` (8px) gap, containing consumer-supplied action slots |
| Badge row | `Wrap` with `dimens.space4` (8px) gap, containing consumer-supplied `ScaffoldBadge` or `ScaffoldChip` slots |
| Padding | `EdgeInsets.all(dimens.space8)` (16px) internal |
| Focus | Focus ring via `ScaffoldFocusOutline` wrapping the whole composer when text field has focus |
| Disabled | `ScaffoldDisabledOverlay` over the whole composer |

### DataColumnConfig\<T\>.cellBuilder (WIDG-43)

| Property | Contract |
|----------|----------|
| Signature | `Widget Function(BuildContext context, T item)? cellBuilder` |
| Default | When null, cell renders `Text(item.accessor?.toString() ?? '')` (existing behavior) |
| When provided | Cell renders `cellBuilder(context, item)` inside the existing `DataCell` |
| Padding | Inherited from `DataTable` default cell padding — custom builders MUST NOT add their own outer padding |
| Typography | Built-in string cells use `textTheme.bodyMedium` — custom builders SHOULD use the same slot for visual alignment |
| Sort header | Unchanged — sort behavior driven by `DataColumnConfig.accessor` regardless of `cellBuilder` |
| Column width | Custom cells inherit the existing `Expanded` column sizing |
| Selection checkbox | Unchanged — first cell is always the selection checkbox |
| Alignment | Custom builders should left-align content to match built-in string cells (or document otherwise) |

### Light Palette Completion (WIDG-46)

| Property | Contract |
|----------|----------|
| Scope | Verify + complete `ScaffoldPalette.lightPalette` so every scaffold widget renders correctly under a default light `ThemeData` |
| Token coverage | All 22 tokens in `ScaffoldPalette` have light values |
| Existing gap | `lightPalette` already exists in `scaffold_palette.dart` — Phase 8 confirms every widget consumes palette tokens (no hardcoded colors) |
| Verification | Per-widget golden or screenshot test under `ThemeData.light()` + `ScaffoldPalette.lightPalette` |
| Contrast | All text/background pairs meet WCAG AA (4.5:1 for body, 3:1 for large text) in BOTH palettes |

## Interaction States (applies to all Phase 8 pressables)

| State | Visual | Source |
|-------|--------|--------|
| Default | No overlay | `ScaffoldPressable` baseline |
| Hover | 8% `palette.textPrimary` overlay | `ScaffoldPressable` existing |
| Pressed | 12% `palette.textPrimary` overlay | `ScaffoldPressable` existing |
| Focus | 2px `palette.focusRingColor` ring via `ScaffoldFocusOutline` | `ScaffoldPressable` existing |
| Disabled | 40% opacity `ScaffoldDisabledOverlay` | `ScaffoldDisabledOverlay` existing |

**Motion:** all transitions use `ScaffoldMotionDurations.short` (150ms) for state-layer fades and `ScaffoldMotionDurations.medium` (300ms) for size/expand transitions, both with `ScaffoldMotionCurves.standard`.

## Accessibility Contract

| Element | Requirement |
|---------|-------------|
| ScaffoldChip | `Semantics(button: true)`; if icon-only, `semanticLabel` is REQUIRED (constructor asserts non-null) |
| ScaffoldChipGroup | `Semantics(role: radiogroup)` for single-select, `Semantics(role: group)` for multi-select |
| ScaffoldDisclosure | `Semantics(expanded: bool, label: title)`; state change announced |
| ScaffoldTraceList | Each item is its own disclosure semantics node |
| ScaffoldComposer | Text field uses M3 default text-field semantics; action slots each carry their own button semantics |
| DataTable cellBuilder | Custom builders MUST supply their own `Semantics` when content is interactive; string cells inherit M3 `DataCell` semantics |
| Touch targets | All pressables meet 48x48 via `ScaffoldTouchTarget` |
| Focus | All pressables show `ScaffoldFocusOutline` focus ring; keyboard activation via Enter/Space |
