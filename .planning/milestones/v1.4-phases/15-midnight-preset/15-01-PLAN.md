  design_tokens.json and no M3 keys. Values with no scaffold field go under a top-level `preset` key
  (plans 15-02 and 15-03). The driver is `scaffold_codegen.generators.theme_presets`. It reuses the
  theme_defaults encoders, templates and splice, so it is the existing codegen with a second region

  const instances, the same marker-region pattern as scaffold_palette.dart. The one call lives in
  `lib/theme/presets/midnight_theme.dart`.

  Source tokens with no scaffold field go into small preset-only const data classes: MidnightColors,
  MidnightShadows, MidnightGradients, MidnightTypeScale, MidnightScale and Midnight.textTheme. No field
  is added to any scaffold extension, so design_tokens.json and lib/theme/scaffold_*.dart do not change
  in this phase. Phase 16 adds extension fields when a widget starts reading these values.
- PD-03 AA over fidelity: where a source value fails a pair the contrast test checks, midnight uses the
  source's own AA-safe token for that role. The deviations are listed in each plan's value table.
- PD-04 Fonts: family names only (`Inter`, `JetBrainsMono`). No font files in lib/ or example/. The
  capture harness registers its Roboto files under these names as stand-ins, the same way it handles
  `monospace` today (plan 15-06).
- PD-05 Text slots: the five TextTheme slots the source leaves unmapped (displaySmall, headlineSmall,
  titleSmall, labelLarge, labelSmall) are left null. They inherit the Material 3 defaults in the preset
  font, which is what the source renders.
