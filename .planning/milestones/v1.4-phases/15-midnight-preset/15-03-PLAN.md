Encoder contract (extends theme_defaults.py; existing outputs must not change):
- Gradient token, one of:
  - `null`: unset, as today
  - linear: `{"type": "linear", "begin": <alignment>, "end": <alignment>, "colors": [<argb>, ...], "stops": [<decimal>, ...]}`
  - radial: `{"type": "radial", "center": [<decimal>, <decimal>], "radius": <decimal>, "colors": [...], "stops": [...]}`

  `stops` is optional. The alignment is one of topLeft, topCenter, topRight, centerLeft, center,
  centerRight, bottomLeft, bottomCenter, bottomRight. Two or more colors, each an uppercase
  "0xAARRGGBB". Stops have the same length as colors, run from 0.0 to 1.0 and never decrease. Any other
  key or type fails with an error that names the entry. The output looks like this:
  - `LinearGradient(begin: Alignment.topCenter, end: Alignment.bottomCenter, colors: [Color(0xFF14171E), Color(0xFF0B0D12), Color(0xFF07090D)], stops: [0.0, 0.4, 1.0])`
  - `RadialGradient(center: Alignment(0.0, -0.9), radius: 1.0, colors: [Color(0x1FFFFFFF), Color(0x00FFFFFF)], stops: [0.0, 0.6])`

  Omit `stops: [...]` when the token has none. An args region still rejects a null literal, so a mode
  without a gradient omits the key.
- Text style token, two new optional keys after the existing four:
  - `lineHeight`, a decimal in px. It needs `fontSize` and emits `height: <lineHeight> / <fontSize>`, a
    const expression that keeps the exact source numbers (PITFALLS 10: height is a multiplier).
  - `tabularFigures`, which must be `true` and emits `fontFeatures: [FontFeature.tabularFigures()]`.

  The emission order is fontFamily, fontSize, fontWeight, letterSpacing, height, fontFeatures.
  `color` stays rejected.
