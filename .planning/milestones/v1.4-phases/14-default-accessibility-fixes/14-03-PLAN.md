<objective>
Fix the light-mode text field and drawer contrast bug (A11Y-02; the GCS ticket in
TICKET-text-entry-field-light-mode-contrast.md) in its own commit, separate from the palette fix
(UD-02). Its re-baselined captures follow in a separate capture commit (UD-03, checker ruling).

Phase 13 (13-02) already moved the hard-coded white in TextEntryFieldWidget and BottomDrawer onto the
color roles inputForeground, sheetForeground and sheetDivider. Their light defaults were kept equal to
the dark ones, to leave Phase 13 pixel-identical, and the 13-02 summary says Phase 14 changes the
values. So this is a token-value change only (UD-04). An app that registers no ScaffoldColorRoles gets
the light values through `fallbackFor(palette, Brightness.light)`, so GCS picks up the fix without
code changes.

Exact value changes (scaffold.colorRoles.light only; dark unchanged):

| Token path | Old | New | Ratio old -> new |
|---|---|---|---|
| scaffold.colorRoles.light.inputForeground | 0xFFFFFFFF | 0xFF17191E (= light textPrimary) | 1.11 -> 15.81 on grayPrimary #F1F3F5 |
| scaffold.colorRoles.light.sheetForeground | 0xFFFFFFFF | 0xFF17191E (= light textPrimary) | 1.18 -> 14.96 on deepBlueTertiary #E9EDF2 |
| scaffold.colorRoles.light.sheetDivider | 0x1FFFFFFF | 0x1F000000 (= light borderSubtle) | white hairline (invisible) -> dark hairline; decorative, so 1.4.11 does not apply |

Output: a `fix(14-03)` commit with the tokens, the regenerated Dart and the tests, then a `chore(14-03)` commit with two light PNGs.
</objective>
