<objective>
Make the default palettes pass WCAG AA in light and dark (A11Y-01, UD-01). Do it by changing token
values only (UD-04), behind a contrast test that Phase 15 extends to midnight (UD-05). Land the fix in one
commit and its re-baselined captures in the next, separate commit (UD-03, checker ruling).

Purpose: The defaults have known AA failures (research PITFALLS 6): the light focus ring at 1.57:1,
gray500 at 3.73 to 4.40, and light statusSuccess at 2.86 to 3.36. Applying the same rule to every
token and surface finds more failures, which this plan also fixes. The light statusError and
statusWarningText fail on the light gray surfaces. The control border (borderGrey, which an
unregistered app's text field uses as its enabled border) fails in both modes. Phase 15 SC4 checks
control-border pairs on the default palettes and may not change defaults, so this phase has to fix
them.

Output: a contrast helper and test (Task 1, its own test-only commit), then the A11Y-01 fix commit
with the token values, the regenerated Dart and the full pair checks, then a capture commit with the
moved PNGs only.

Exact value changes (ratios are on the worst surface of that mode; Flutter's float math may differ in
the second decimal):
