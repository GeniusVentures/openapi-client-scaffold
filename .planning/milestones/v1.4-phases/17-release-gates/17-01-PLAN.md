Planner decisions (Claude's discretion, shared by the three plans and the verifier):
- PD-01 Location. The gate is `tools/capture_gate.py`, stdlib only, importing `REPO_ROOT` from
  `scaffold_codegen` (CLAUDE.md: repo paths come from those constants). It is not part of
  `scaffold_codegen` because it is not codegen. The manifest is `tools/capture_rebaselines.json`, not
  under images/, because images/ holds only PNGs. pytest already has `pythonpath = ["tools"]`, so
  tests `import capture_gate`; `python tools/capture_gate.py` works without PYTHONPATH because
  sys.path[0] is tools/.
- PD-02 One sanction mechanism: the manifest. Historical commits cannot carry trailers, so a second
  mechanism would only add surface. Workflow for a future re-baseline: the fix commit, then a
  PNG-only capture commit, then a commit adding its manifest entry. Local pytest fails between the
  last two, which is the reminder.
- PD-03 Rules, evaluated over every commit in the range that touched images/:
  - R1 sanction: an unlisted commit with any image path whose status is not A (so M, D, R, C or T)
    is a violation. Commits that only add PNGs are allowed (new demos add captures).
  - R2 PNG only under images/: any changed path under images/ that does not end in .png is a
    violation, listed or not.
  - R3 isolation: a listed commit that changes any path outside images/ is a violation.
  - R4 scope: an entry with scope `midnight` may change only paths under images/midnight/; scope
    `default` may change no path under images/midnight/.
  - R5 identity: a listed commit's subject must equal the entry's `subject`; when `follows` is set,
    the commit's first parent must equal it.
  - R6 completeness: every manifest entry must match a commit in the range.
  - Manifest validation at load (a bad manifest is a setup error, exit 2): top-level keys exactly
    `base` and `rebaselines`; entry keys exactly `sha`, `subject`, `scope`, `follows`, `record`;
    `base`, `sha` and a non-null `follows` are 40 lowercase hex; `scope` is `default` or
    `midnight`; `subject` and `record` are non-empty strings; SHAs are unique.
  - Renames and copies count both the old and the new path.
- PD-04 Reading git. Range: `git rev-list --reverse --full-history --no-merges <base>..<head> -- images`.
  Per commit: `git diff-tree --no-commit-id -r -z --name-status -M <sha>` (all paths, not
  path-limited, so R3 sees non-image files), and `git show -s --format=%P%x00%s <sha>` for the
  first parent and subject. Merge commits are skipped: develop has no merges since the base, and
  CI pull_request runs check out a synthetic merge. The limitation (a squash or rebase merge
  rewrites SHAs and fails the gate loudly) is documented in 17-03.
- PD-05 Unreachable base. Before reading, `git merge-base --is-ancestor <base> <head>`; non-zero
  raises `GateError` with a message naming the base and "fetch-depth: 0". The CLI exits 2; the
  pytest test fails, it does not skip.
- PD-06 Render check is local only. Rasterization differs between machines (12-VERIFICATION note
  on truth 5; d9342ff re-rendered every capture on this machine), so CI cannot compare bytes. The
  render subcommand writes to a temp dir through `SCAFFOLD_CAPTURE_DIR` (passed as a POSIX-style
  path, as the earlier `cygpath -m` runs did), compares every PNG under images/ recursively by
  relative path and bytes, deletes the scratch dir on success and keeps and prints it on failure.
- PD-07 "Existing capture" in roadmap SC1 means the 52 default PNGs present at e67e00c. The midnight
  captures did not exist at the base; they were added and re-baselined only in the isolated chore
  commits sanctioned by UN-01. The 17-03 audit states this reading.
- PD-08 Exit codes: 0 pass, 1 violations or differences, 2 setup error (bad manifest, unreachable
  base, flutter not found, harness run failed).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contributor commit -> develop history | a capture can change in any commit; the gate decides whether that change was sanctioned |
| manifest file -> gate | the manifest is the list of sanctions; editing it is how a change gets sanctioned |
| CI checkout -> gate | a shallow checkout hides the base and could make the gate vacuous |
